# 产品架构

## 设计目标

长篇创作的核心不是扩大模型上下文窗口，而是把长期资料治理为“何时可用、何时必须遵守、何时不应出现”的上下文。系统因此将作者资产、模型解析候选和当前写作任务分开管理。

## 上下文链路

1. 作者导入或维护章节、章纲、人物、线索和写作要求。
2. 创建章节快照，快照最后章节成为知识截止点。
3. 系统基于当前断点与写作目标检索截止点前的相关证据。
4. 仅选择直接相关、作者已锁定且仍在有效范围内的约束，最多注入 6 条。
5. 将续写目标、检索证据、锁定约束、场景边界和输出格式分层拼装后调用模型。
6. 对返回文本执行完整性与一致性检查，再交由作者修改、保存或重跑。

## 三种续写策略

| 策略 | 上下文 | 适用场景 |
| --- | --- | --- |
| 快速续写 A | 最近正文 + 作者本次要求 | 快速获取方向性草稿。 |
| 深度续写 B | A + RAG 检索证据 | 需要利用人物、线索、章纲等长线资料。 |
| 指令续写 C | B + 作者锁定的相关约束 | 作者希望对当前场景施加明确边界。 |

## 幻觉控制边界

- 知识截止点阻止使用未来章节资料。
- 作者确认与锁定的资料优先于模型推断。
- 对开放创作允许低影响文学化补全，但限制新增人物、地点、组织、既往经历和主线因果。
- 输出异常不直接进入质量评审：先处理空响应、超时、JSON 格式异常与明显截断。

## 技术组件

- Next.js + React：创作工作台和开发者工具。
- PostgreSQL + pgvector：作品、资料、快照、向量检索与运行记录。
- OpenAI-compatible API：生成、解析、Judge 与嵌入服务可独立配置。
- 结构化输出恢复：面向解析与 Judge 的 JSON 提取、修复与 schema 校验。
